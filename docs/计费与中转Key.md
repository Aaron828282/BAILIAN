# 计费与中转 Key

版本：1.1.0。本站使用经营者自行填写的人民币售价，未预填或声称同步阿里官方价格。

## 操作顺序

1. 登录管理台，在“计费标准”填写需要提供的模型规格价格并保存。
2. 在“Key 号池”添加阿里 Key，或在“加密 Key 包”拖拽导入现有包；检查上游逐模型预算。
3. 进入“中转 Key”，填写名称、初始人民币额度、允许模型和可选有效期，创建独立调用凭据。
4. 将生成的中转 Key 和 Base URL 交给对应调用方。阿里原始 Key 保留在服务器。
5. 在中转 Key 列表查看可用余额、已消费、预占；通过“调用记录”查看该 Key 的请求和费用。需要追加预算时使用“增加额度”。
6. 停用或到期后拒绝新调用，已经提交的任务仍按原价结算。

## 单价和费用

| 类型 | 单价单位 | 实际费用 |
| --- | --- | --- |
| 文本 | 输入、输出各自的元 / 百万 Token | （输入 Token × 输入单价 + 输出 Token × 输出单价）÷ 1000000 |
| 图片 | 元 / 张 | 实际输出张数 × 单价 |
| 视频 | 对应分辨率的元 / 秒 | 实际输出秒数 × 对应分辨率单价 |

空白表示未配置，计费 Key 无法调用该规格。文本必须同时填写输入、输出单价；明确填写 0 才代表免费。视频分别配置 480P、720P、1080P 中该模型支持的规格。

金额支持六位小数，以百万分之一元整数保存。每个请求最终费用向上取整到 0.000001 元；文本的输入和输出费用合并后取整。接口返回人民币元，后台在必要时显示六位小数。

文本上游须提供完整输入和输出用量，且两者之和等于总 Token；只提供总 Token 时保留预占并进入待核对。缓存命中、思考 Token 等未设置独立优惠价，按上游汇总的输入、输出数量使用所设单价。图片按输出张数收费；视频按输出时长、模型和分辨率收费，不额外区分音频或参考素材的供应商成本。经营者应在售价中自行覆盖这些成本。

## 余额与异常

累计授予额度是管理员为中转 Key 设定的人民币预算。余额 = 累计授予 − 已消费；可用余额 = max(0, 余额 − 预占)。增加额度不接入支付渠道，不证明现金到账，不向阿里账户充值。

提交前同时检查上游模型预算、Key 状态、模型权限、价格和下游余额。文本按估计输入及 max_tokens 预占，图片按张数、视频按请求时长预占；实际完成后释放预占并记入实际消费。

请求保存提交时的价格快照，调整价格只影响后续新请求。明确失败的请求释放预占；网络中断、超时、5xx、用量缺失等结果不明情况保留预占，避免误判免费并重复生成。管理员根据阿里实际记录进行核对后，按原价一次结算。若实际用量超过预占，则如实扣费，余额可能出现负数，后续无法获得不足以支付的新预占。

相同中转 Key 和 Idempotency-Key 的请求重放只返回原结果，不重复收费；不同中转 Key 之间的幂等值和查询权限隔离。中转 Key 的使用者可通过 /v1/balance、/v1/pricing、/v1/usage 查询自己的余额、价格和账单。

## 上游预算与旧令牌

“额度预设”中的 Token、张数和秒数是每把阿里 Key 的本地用量限制。“中转 Key”中的人民币额度是调用方预算。两层限制分别保留并同时执行，都不代表阿里实时余额或免费额度。

升级前的 RELAY_TOKEN 显示为“旧版共享令牌”，保留不计费行为，不追收历史请求。新用户使用后台创建的计费 Key；旧调用方迁移后，管理员可停用旧令牌。旧令牌不能用于查询新中转 Key 的请求。

## 归档备忘

所有价格与余额都保存在 SQLite 中，备份必须同时保管原 VAULT_KEY。单价配置、额度调整、凭据查看和最终扣费留有记录。交付测试使用隔离模拟数据，没有产生真实阿里费用。正式使用前填好售价，再用受控额度验证目标服务器与真实模型的调用链路。
